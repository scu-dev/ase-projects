# CodeCounter

使用 Python 3.12、Tkinter 和 ttk 的本地代码统计工具，文件夹拖放使用 tkinterdnd2。扫描、行分类和函数识别均在 Python 中实现，不调用现有 C/Rust 统计程序。

## 运行

在当前目录执行：

```powershell
uv run main.py
```

需要使用包含 Tcl/Tk 的 Python 解释器。`uv run` 会安装项目声明的 tkinterdnd2 依赖。已初始化并同步本地虚拟环境时，也可以执行：

```powershell
.\.venv\Scripts\python.exe main.py
```

可以传入初始目录，也可以使用控制台模式：

```powershell
uv run main.py ..\.local\testcase3
uv run main.py --cli ..\.local\testcase3
```

未传入目录时使用当前工作目录。控制台模式正常结束返回 0；路径无效或存在读取失败时返回 1；参数错误返回 2。

## 统计目标

表格严格使用 [参考表](testcase3_测试结果.jpg) 中的十列：

| 语言 | 源文件数 | 代码行数 | 空行数 | 注释行数 | 函数个数 | 最大值 | 最小值 | 均值 | 中位数 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

按 C、C++、JAVA、Python、C# 分行显示。后四列按语言汇集所有已识别的函数，每个函数提供一个样本，取值为它的**代码行数**。

函数从签名起始行计到函数体末尾，包含跨行签名、独占一行的花括号及代码与注释混写的行，跳过空行和纯注释行。Python 从 `def` 或 `async def` 开始，独立的装饰器位于范围以外。嵌套函数单独取样，外层函数的长度也包含这段代码。

最大值和最小值分别是该语言最长和最短函数的代码行数。均值用所有函数的代码行数之和除以函数个数。中位数取排序后的中间值，函数个数为偶数时取中间两项的平均。均值和中位数显示两位小数。

只有全局代码的文件和空文件都计入源文件数，并提供零个函数样本。某种语言的函数个数为零时，后四列均显示为零。

## 文件识别与扫描

递归扫描所选目录及其子目录，扩展名不区分大小写：

| 语言 | 扩展名 |
| --- | --- |
| C | .c、.h |
| C++ | .cpp、.cc、.cxx、.hpp、.hh、.hxx、.ipp、.inl |
| JAVA | .java |
| Python | .py、.pyi、.pyw |
| C# | .cs、.csx |

`.h` 按原版规则归入 C。不按 Git 忽略规则过滤目录；符号链接和 Windows 重解析点会跳过，防止重复统计或循环遍历。

支持 UTF-8、带 BOM 的 UTF-16/UTF-32；其他 ASCII 兼容编码保留原有语法字节进行统计。编码损坏或文件无法读取时记录错误并继续处理其他文件，失败文件不参与统计。

含 NUL 字节的非 BOM 文本、带 JPEG/PNG 文件头的文件会作为二进制静默跳过，不弹窗，也不显示跳过数量。原 `testcase2` 中的 150 个文件实际均为改了源码后缀的 JPEG，因此不计入源文件数和代码量。

## 行数口径

沿用 `week2-codecounter` 源码中保留的物理行分类规则：

- 每行只归入代码、空行、注释中的一类；同一行同时含代码和注释时算代码行。
- 仅含空格、制表符等 ASCII 空白字符的行算空行；块注释内的空白行算注释行。
- 字符串中的注释标记不算注释。Python 文档字符串和其他三引号字符串算代码，字符串内部的纯空白行仍算空行。
- 识别单行注释、块注释、转义引号、C/C++ 续行注释、C++ 原始字符串、Java 文本块、Python 三引号与 f-string，以及 C# 逐字、插值和原始字符串。
- 支持 LF、CRLF、CR；文件末尾单个换行符不会凭空增加一行，空文件为零行。

## 函数计数口径

按源码中的函数定义计数，包括普通函数、方法、构造函数、析构函数、常见运算符函数和局部函数；Python 的 async def、带省略号函数体的 stub，以及 C# 表达式体方法也计入。

不把调用、注释或字符串里的函数文本、普通函数原型、无函数体的抽象声明、lambda/匿名函数、C# 属性访问器计入函数数。C/C++ 预处理指令本身不计为函数，也不展开宏或求值条件编译。

函数识别采用纯标准库词法分析，不是完整的编译器语法解析。复杂宏、特殊模板/声明形式、语言扩展或不完整源码可能影响函数计数，不能将它视为编译器级的精确语义指标。

## 界面行为

- 点击“选择文件夹”，选定后立即开始统计；取消选择保留现有目录和结果。
- 向窗口任意区域拖入一个文件夹后立即开始统计。拖入文件、多个项目、文本或无效路径时直接弹窗报错，保留现有目录和结果。
- 也可以手动修改路径，然后在路径输入框中按 Enter 开始统计。
- 扫描在后台线程运行，界面显示已处理文件数和耗时。
- 扫描期间禁止更换目录；此时拖入文件夹会提示先取消或等待当前统计完成。
- 点击“取消”保留已经完成读取的文件统计；关闭窗口也会通知扫描停止。
- 读取失败时明确标注结果不完整，扫描结束后自动弹窗汇总失败路径和原因；路径无效或扫描异常时直接弹窗提示。
- 重复统计会替换旧结果；更换目录会清空旧结果，避免把上一目录的统计当成新结果。

## 导出结果

统计结束后，点击右上角“导出 CSV…”、“导出 XLSX…”或“导出 HTML 可视化...”，选择保存位置。导出使用当前表格的五种语言、十列数据；取消扫描或发生部分读取失败后，也可以导出当前已完成的结果。

- CSV 使用带 BOM 的 UTF-8 编码，包含中文表头，均值和中位数保留两位小数。
- XLSX 包含“代码统计”工作表，数值保存为数字；均值和中位数保留原始精度并显示两位小数。首行冻结，表头支持筛选。
- HTML 为单个文件，双击即可在浏览器中离线查看；样式、图表和数据均包含在文件内，不访问网络。
- 未产生结果、正在扫描或更换目录后，导出按钮不可用；重新统计结束后导出最新结果。
- 取消保存不会生成文件；保存失败直接弹窗，写入失败时保留原文件。
- 三种格式都使用 Python 标准库生成，无需安装 Excel 或第三方包。

HTML 报告包括：

- 目录路径、源文件数、代码行数、函数个数；取消或读取失败的结果会标注为不完整。
- 函数长度分布：按全部语言或单种语言查看，分组为 1–5、6–10、11–20、21–50、51–100、101 行以上，显示各组函数数及占比。最大值、最小值、均值和中位数随所选语言更新；全部语言的统计按所有函数样本汇总。
- 各语言行数构成：代码行、注释行和空行的堆叠条形图，可切换绝对行数与百分比。绝对行数共用刻度，百分比以各语言的总行数为分母。
- 与界面一致的五种语言、十列统计明细。没有函数的范围显示空状态，统计数值为零。

## 测试

使用标准库 unittest：

```powershell
uv run python -m unittest discover -s tests -v
```

测试覆盖行分类、函数定义识别、按函数代码行数汇总的统计分布、编码、二进制伪装文件、目录递归、符号链接、读取失败、取消、CSV/XLSX/HTML 导出和 GUI 状态恢复；GUI 测试还覆盖选定文件夹后自动统计、原生拖放事件分发及无效拖入；HTML 测试还覆盖分组边界、全部语言汇总、空结果、部分结果和文本转义。GUI 测试需要本地可用的 Tk 窗口环境及 tkinterdnd2。

## 文件

- `main.py`：Tkinter 界面、后台扫描协调和命令行入口。
- `counter.py`：文件识别、词法扫描、函数计数和统计汇总。
- `exporter.py`：使用标准库生成 CSV 和 XLSX，安全写入三种格式的导出文件。
- `html_report.py`、`report_template.html`：生成 HTML 报告的数据、统计表和交互图表。
- `tests/`：核心逻辑及 GUI 回归测试。
- `pyproject.toml`：项目元数据及 tkinterdnd2 拖放依赖。
- `.python-version`：固定使用 Python 3.12。
- `uv.lock`：uv 项目锁文件。
