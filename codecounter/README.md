# CodeCounter

使用 Python 3.12、Tkinter 和 ttk 的本地代码统计工具，无第三方包依赖。扫描、行分类和函数识别均在 Python 中实现，不调用现有 C/Rust 二进制。

## 运行

在当前目录执行：

```powershell
uv run main.py
```

需要使用包含 Tcl/Tk 的 Python 解释器。已初始化本地虚拟环境时，也可以执行：

```powershell
.\.venv\Scripts\python.exe main.py
```

可以传入初始目录，也可以使用控制台模式：

```powershell
uv run main.py ..\.local\testcase3
uv run main.py --cli ..\.local\testcase3
```

未传入目录时使用当前工作目录。控制台模式正常结束返回 0；路径无效或存在读取失败时返回 1；参数错误返回 2。

## 统计目标

表格严格使用 [参考表](testcase3_测试结果.jpg) 中的十列：

| 语言 | 源文件数 | 代码行数 | 空行数 | 注释行数 | 函数个数 | 最大值 | 最小值 | 均值 | 中位数 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

按 C、C++、JAVA、Python、C# 分行显示。后四列均由该语言下**每个源文件的代码行数**派生，与函数长度无关：

- 最大值、最小值：各文件代码行数的最大值和最小值。
- 均值：代码行数合计除以源文件数。
- 中位数：将各文件代码行数排序，取中间值；文件数为偶数时取中间两个值的平均。
- 空文件也计入源文件数，并以 0 行参与计算；没有源文件时各项显示为 0。
- 均值和中位数显示两位小数。

## 文件识别与扫描

递归扫描所选目录及其子目录，扩展名不区分大小写：

| 语言 | 扩展名 |
| --- | --- |
| C | .c、.h |
| C++ | .cpp、.cc、.cxx、.hpp、.hh、.hxx、.ipp、.inl |
| JAVA | .java |
| Python | .py、.pyi、.pyw |
| C# | .cs、.csx |

`.h` 按原版规则归入 C。不按 Git 忽略规则过滤目录；符号链接和 Windows 重解析点会跳过，防止重复统计或循环遍历。

支持 UTF-8、带 BOM 的 UTF-16/UTF-32；其他 ASCII 兼容编码保留原有语法字节进行统计。编码损坏或文件无法读取时记录错误并继续处理其他文件，失败文件不参与统计。

含 NUL 字节的非 BOM 文本、带 JPEG/PNG 文件头的文件会作为二进制静默跳过，不弹窗，也不显示跳过数量。原 `testcase2` 中的 150 个文件实际均为改了源码后缀的 JPEG，因此不计入源文件数和代码量。

## 行数口径

沿用 `week2-codecounter` 源码中保留的物理行分类规则：

- 每行只归入代码、空行、注释中的一类；同一行同时含代码和注释时算代码行。
- 仅含空格、制表符等 ASCII 空白字符的行算空行；块注释内的空白行算注释行。
- 字符串中的注释标记不算注释。Python 文档字符串和其他三引号字符串算代码，字符串内部的纯空白行仍算空行。
- 识别单行注释、块注释、转义引号、C/C++ 续行注释、C++ 原始字符串、Java 文本块、Python 三引号与 f-string，以及 C# 逐字、插值和原始字符串。
- 支持 LF、CRLF、CR；文件末尾单个换行符不会凭空增加一行，空文件为零行。

## 函数计数口径

按源码中的函数定义计数，包括普通函数、方法、构造函数、析构函数、常见运算符函数和局部函数；Python 的 async def、带省略号函数体的 stub，以及 C# 表达式体方法也计入。

不把调用、注释或字符串里的函数文本、普通函数原型、无函数体的抽象声明、lambda/匿名函数、C# 属性访问器计入函数数。C/C++ 预处理指令本身不计为函数，也不展开宏或求值条件编译。

函数识别采用纯标准库词法分析，不是完整的编译器语法解析。复杂宏、特殊模板/声明形式、语言扩展或不完整源码可能影响函数计数，不能将它视为编译器级的精确语义指标。

## 界面行为

- 输入路径后点击“开始统计”，也可以在路径输入框中按 Enter。
- 扫描在后台线程运行，界面显示已处理文件数和耗时。
- 点击“取消”保留已经完成读取的文件统计；关闭窗口也会通知扫描停止。
- 读取失败时明确标注结果不完整，扫描结束后自动弹窗汇总失败路径和原因；路径无效或扫描异常时直接弹窗提示。
- 重复统计会替换旧结果；更换目录会清空旧结果，避免把上一目录的统计当成新结果。

## 导出结果

统计结束后，点击右上角“导出 CSV…”或“导出 XLSX…”，选择保存位置。导出使用当前表格的五种语言、十列数据；取消扫描或发生部分读取失败后，也可以导出当前已完成的结果。

- CSV 使用带 BOM 的 UTF-8 编码，包含中文表头，均值和中位数保留两位小数。
- XLSX 包含“代码统计”工作表，数值保存为数字；均值和中位数保留原始精度并显示两位小数。首行冻结，表头支持筛选。
- 未产生结果、正在扫描或更换目录后，导出按钮不可用；重新统计结束后导出最新结果。
- 取消保存不会生成文件；保存失败直接弹窗，写入失败时保留原文件。
- 两种格式都使用 Python 标准库生成，无需安装 Excel 或第三方包。

## 测试

使用标准库 unittest：

```powershell
uv run python -m unittest discover -s tests -v
```

测试覆盖行分类、函数定义识别、文件级统计分布、编码、二进制伪装文件、目录递归、符号链接、读取失败、取消、CSV/XLSX 导出和 GUI 状态恢复。GUI 测试需要本地可用的 Tk 窗口环境。

## 文件

- `main.py`：Tkinter 界面、后台扫描协调和命令行入口。
- `counter.py`：文件识别、词法扫描、函数计数和统计汇总。
- `exporter.py`：使用标准库生成 CSV 和 XLSX，安全写入导出文件。
- `tests/`：核心逻辑及 GUI 回归测试。
- `pyproject.toml`：项目元数据，第三方依赖为空。
- `.python-version`：固定使用 Python 3.12。
- `uv.lock`：uv 项目锁文件。
